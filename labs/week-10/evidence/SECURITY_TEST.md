## ผลการทดสอบ SQL Injection

### 1. ทดสอบเงื่อนไขที่เป็นจริงเสมอ

* **ยิง:** `GET http://localhost:3001/api/requests?status=x%27%20OR%20%271%27%3D%271`
* **ผลที่ได้:** `[]` (0 รายการ)
* **เพราะ:** ระบบใช้ Parameterized Query ทำให้ค่าที่ส่งเข้ามาถูกมองเป็นข้อมูลแบบ String ไม่ได้ถูกนำไปประมวลผลเป็นคำสั่ง SQL จึงไม่สามารถทำให้เงื่อนไข `OR '1'='1'` ทำงานได้

### 2. ทดสอบพยายามลบตาราง

* **ยิง:** `GET http://localhost:3001/api/requests?status=%27%3B%20DROP%20TABLE%20requests%3B%20--`
* **ผลที่ได้:** `[]` (0 รายการ) และเมื่อเรียก `GET /api/requests` อีกครั้ง ข้อมูลยังสามารถเรียกดูได้ตามปกติ ตาราง `requests` ไม่ถูกลบ
* **เพราะ:** คำสั่ง `DROP TABLE requests` ที่ส่งเข้ามาถูกมองเป็นค่าข้อมูล String ของ parameter ไม่ได้ถูก SQLite ประมวลผลเป็นคำสั่ง SQL จึงไม่สามารถลบตารางได้

### 3. ทดสอบต่อเงื่อนไขเพิ่มเติม

* **ยิง:** `GET http://localhost:3001/api/requests?status=pending%27%20OR%20status=%27completed`
* **ผลที่ได้:** `[]` (0 รายการ)
* **เพราะ:** ค่าที่ส่งเข้ามาทั้งหมดถูกส่งเป็น Parameter เดียว ทำให้ระบบค้นหา `status` ที่มีค่าเป็นข้อความ `pending' OR status='completed` ซึ่งไม่มีอยู่จริง จึงไม่สามารถใช้ `OR` เพื่อดึงข้อมูลเพิ่มเติมได้

### สรุปผล

ผลการทดสอบทั้ง 3 กรณีพบว่า SQL Injection ไม่สามารถเปลี่ยนแปลงคำสั่ง SQL หรือเข้าถึงข้อมูลเพิ่มเติมได้ เนื่องจาก API ใช้ Parameterized Query ในการรับค่าจากผู้ใช้ ทำให้ค่าที่ส่งเข้ามาถูกปฏิบัติเป็นข้อมูล ไม่ใช่คำสั่ง SQL
